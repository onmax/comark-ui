# comark-ui

Comark plugins for review documents: annotated screenshots, before/after comparisons, suggested code changes, charts, and icons. Agents write most of the documents they render, often as PR evidence. Because of that, the issue messages are as important as the HTML: every one names its block and says how to fix it.

## Shape

A pnpm workspace. Every package in `packages/` is published to npm under its own name, and all of them share one version. Each `tsdown.config.ts` is one call to `definePackage()` or, for a package with a renderer per framework, `defineComponentsPackage()` from the root `tsdown.shared.ts`, so the packages build alike.

- `packages/annotate` is `comark-annotate`.
  - `src/read.ts` reads `::screenshot`, `::compare`, and `::annotation` nodes and reports their issues. The plugin and the renderer both go through it, so they can't disagree.
  - `src/index.ts` is the parse plugin. It appends its problems to `meta.issues`.
  - `src/html.ts` is the `@comark/html` renderer. The output reads without a script; the zoom and carousel scripts and all styles are inlined once per document. A screenshot zooms with `comark-zoom`, and `::compare` is a two-column `comark-carousel`. Marks are not links, so a click anywhere on a screenshot zooms it.
  - Only the HTML renderer exists: notes are Markdown, and Vue, React, and Svelte versions would each copy the whole figure template.
  - `src/marks.ts` holds the hand-drawn marks, taken from AnnotationKit, and `src/script.ts` is the browser script the HTML renderer inlines.
- `packages/carousel` is `comark-carousel`. Its parse plugin turns `::carousel` content into explicit `slide` nodes with their position, so no renderer splits children. Its script is built like zoom's, and a carousel is a zoom gallery.
- `packages/cast` is `comark-cast`. Its parse plugin reads an asciinema v2 or v3 cast from `src` (read like comark-include, under `root` or through `read`) or from a code block inside `::cast`, replays its output through the small terminal in `src/term.ts`, and replaces the node's children with the final screen, or with `mode="log"` every line printed, as text and `span` nodes with `cca-` color classes or a hex `style`. No player and no script. The HTML renderer writes those spans itself, because the renderer's pretty-printing would break the lines of a `pre`.
- `packages/charts` is `comark-charts`. `src/read.ts` checks a `::chart` and its table, or the `vega-lite` spec that draws any other chart over the table, and the parse plugin draws it with Flint and Vega and replaces its attributes with `type`, `title`, `label`, `svg`, and `marks`, keeping only the table as content, so no renderer loads Vega. Marks need comark-annotate's figure, so only the HTML renderer draws them.
- `packages/chips` is `comark-chips`. Its parse plugin turns every web link, `@user`, and `:chip` into a `chip` node with `href`, `kind` (`favicon` or `avatar`), `src`, and `title`, so no renderer reads URLs. `src/images.ts` downloads each image while parsing and inlines it as a data URI, cached per process; an HTTP error maps to its status, and any other failure keeps the URL for the reader's browser. No script: the components add the styles on mount.
- `packages/colors` is `comark-colors`. Its parse plugin turns inline code that holds a hex, rgb(), hsl(), hwb(), lab(), lch(), oklab(), or oklch() color into a `color` node with `value`, and a `::palette` list of `name: color` lines into `color` nodes with `name` too, so no renderer reads colors. The color pattern admits only the characters a color needs, since renderers write it into a style attribute. No script: the components add the styles on mount.
- `packages/cjk` is `comark-cjk`, markdown-it-cjk-friendly run unchanged, so `**` and `*` close next to Chinese, Japanese, and Korean punctuation. No components and no styles, so it works in any renderer.
- `packages/code` is `comark-code`. Its components replace `pre`: each wraps the block, rendered as it would be without them, in `.ck` with a bar of buttons, so Shiki's output and code groups work in any plugin order. The bar's markup is one string from `buttons()` in `src/client.ts` that every renderer inlines. Its parse plugin only writes the configured `actions` onto matching `pre` nodes; the script sends a `comark-code-action` event for them and does nothing else.
- `packages/critic` is `comark-critic`. An inline rule placed before Comark's attribute rule, which would otherwise drop `{++add++}`, reads CriticMarkup inside one paragraph into native `ins`, `del`, and `mark` spans with `ccm-` classes, so its styles never reach a `~~strikethrough~~`'s `del`, and a `.ccm-comment` span; `mode` accepts or rejects the changes while tokenizing. A mark left open goes to `meta.issues` through a token that `markdownItPost` collects. Comark sets the class from a `{.class}` after a mark in place of the mark's own, so `markdownItPost` writes both into those props. No renderer: `css` holds the marks' styles, and the docs site appends it to its own.
- `packages/deflist` is `comark-deflist`, markdown-it-deflist ported to push block tokens Comark builds with any tag, so `Term` then `: Definition` renders as native `dl`, `dt`, and `dd` with no classes and no renderer.
- `packages/diagrams` is `comark-diagrams`. Its parse plugin sends each plantuml, graphviz/dot, d2, dbml, goat, or svgbob fence to a Kroki server (`server`, default kroki.io), caches the drawing per process like comark-chips, sanitizes it with `src/sanitize.ts`, and replaces the fence with a `diagram` node holding `type`, `svg`, and `label`. A fence it can't draw stays code. No script: the components add the styles on mount.
- `packages/code-notes` is `comark-code-notes`. Its `markdownItPost` strips `<1>` markers in a line-end comment from every fence an ordered list follows, so Shiki highlights clean code in any order, and its `post` draws them as `a.cn-marker` nodes into Shiki's line spans (or its own) and turns the list into a `code-notes` node. Drawing needs Shiki's lines, so it goes after `shiki` in `plugins`, and it reports the other order; `highlighted()` in `docs/build.ts` places Shiki before comark-code and it. The number is CSS content, so comark-code's Copy never takes it. No script.
- `packages/diff` is `comark-diff`. `src/read.ts` reads a `::diff` node, two fenced blocks before and after, into rows with a small LCS over lines and then over the words of each changed pair, and reports its issues; the plugin and the renderer both go through it. The HTML renderer draws a table with no script that doesn't zoom: its code scrolls in place. It bundles only `comark-zoom/theme`, like github-callouts.
- `packages/embed` is `comark-embed`. Its parse plugin reads the player's `src` from the `::embed` link alone, with no fetch, and replaces the node's attributes with `provider`, `src`, `label`, `size`, `href`, `title`, and `host`, so no renderer parses URLs. `src/providers.ts` holds one entry per provider. A link with no player becomes a card, and one that isn't https renders nothing. No script: the components add the styles on mount.
- `packages/footnotes` is `comark-footnotes`, named `footnotes` so it replaces `comark/plugins/footnotes`. markdown-it-footnote's block and inline rules mark definitions, references, and inline notes with `cfn-` tags, and `post` numbers them and writes core's nodes and unprefixed classes (`footnote-ref`, `footnotes`), so styles made for core keep working; it's the one package whose classes don't carry its prefix. A streaming parse reuses numbered references, so a WeakMap keeps what each stood for.
- `packages/math` is `comark-mathml`, since npm refuses `comark-math` as too close to `remark-math`. Its plugin is named `math` so it replaces `comark/plugins/math`. Its inline and block rules read `$…$`, `\(…\)`, `$$…$$`, and `\[…\]` (a `$` before a digit, and `\[1\]`, stay text), and `markdownItPost` turns `math` fences into the same token, so Comark builds its own `math` nodes. `post` typesets every one with Temml into MathML, or with KaTeX's HTML when `output` asks and `katex` is installed, cached per process in `src/typeset.ts`, and replaces each with a `formula` node holding `tex`, `display`, and `html`, so no renderer loads a typesetter. A formula that fails keeps no `html` and renders its escaped TeX; a `$$` that Comark closed at the end of a stream fails without an issue. No script: the components add the styles on mount.
- `packages/media` is `comark-media`. Its `markdownItPost` turns an image whose `src` ends in a video or audio extension, and a bare GitHub `user-attachments` link alone in a paragraph, into a `media` token, before any plugin's `post`, so comark-zoom and comark-chips never see them whatever the order. Its `post` replaces the node's attributes with `kind`, `src`, `label`, `poster`, `autoplay`, `loop`, `muted`, and `native` when the `controls: "native"` option is set. Otherwise the renderers wrap the `<video controls>` or `<audio controls>` in `.cm-video` or `.cm-audio` with a bar of controls, one string from `controls()` in `src/client.ts` that every renderer inlines. The script in `start()` marks each player `data-media-ready` to show the bar, and drops a video's own controls, so the browser's controls show without the script and when the file can't play. Its script is built like carousel's.
- `packages/metrics` is `comark-metrics`. Its parse plugin works out each `:delta`'s arrow, percent, and verdict, renames `:progress` to `progress-bar` with its percent so a raw `<progress>` never reaches a component, and replaces `::stats` with its table plus a Change column of `delta` cells, or with `tiles` with a `stat-tiles` node of `div` tiles holding a `dt` name, a `dd` value, and a `delta`, so the renderers only draw. No script: the components add the styles on mount.
- `packages/github` is `comark-github`: the parts of GitHub's Markdown that Comark doesn't render like GitHub, as three named plugins and no default export.
  - `callouts()` in `src/callouts.ts` is named `alert`, so Comark's dedupe swaps it in for the built-in alert plugin and it always sees the raw `[!TYPE]` marker. It turns those blockquotes into `github-callout` nodes with `type` and `title`; the renderers only draw them. No script: the components add the styles on mount.
  - `references()` in `src/references.ts` turns `@user`, `#123`, and `owner/name#123` in text into plain `a` nodes, so no renderer needs a component.
  - `html()` in `src/raw-html.ts` is named `html`, so it replaces Comark's built-in html plugin, reuses its tokenizer, and prunes the nodes marked `$.html` to GitHub's allowlist.
- `packages/icon` is `comark-icon`.
  - `src/resolve.ts` is the resolver: `createIcons()` resolves `set:name` (or Nuxt UI's `i-set-name`) from `collections`, else the Iconify API, into a data URI with its ratio and whether it paints in `currentColor`. Downloads are cached per process across instances; a failed one isn't kept. `describeIconProblem()` words each problem, so every plugin that draws icons reports them alike.
  - `src/index.ts` is the parse plugin. It resolves every `:icon` in one call and writes `src`, `ratio`, `mask`, and `label` on the node, and drops one it can't draw. `name` stays, so a renderer that maps `icon` to Nuxt UI's component still works.
  - An icon is a `.ci` span with its image in `--ci`: a mask over `currentColor` when the SVG uses it, a background image otherwise. The renderers set the style as an object, because `@comark/react` splits a style string at every colon and would cut the data URI.
  - Plugins that draw icons (tabs) take an `Icons` and draw with `iconHtml()`/`iconStyles()` from `/html` and the `Icon` component from `/vue`, `/react`, and `/svelte`.
- `packages/keys` is `comark-keys`. Its inline rule reads `++ctrl+shift+k++` into a `.ckb` span of `kbd` keys joined by `+`, with pymdownx.keys' names and aliases in `src/keys.ts`, so no renderer reads key names. One unknown name leaves the shortcut as text, and `++` after a letter, `+`, or `{` (comark-critic's insertion) never opens one. No styles.
- `packages/lint` is `comark-linter`, a library, CLI, and Vite Doctor extension that lints Comark documents. npm refuses `comark-lint` as too close to `remark-lint`, so the package is `comark-linter` and its command and config file are `lint-comark`.
  - `src/index.ts` is `lint()`. Comark gives nodes no positions, so block components take their line from markdown-exit tokens (plus the stripped frontmatter's lines) and everything else is found by searching the source with fenced code blanked out.
  - `src/links.ts` checks every `href` and `src`: files and their anchors through the `read`/`exists`/`list` options (Doctor passes `ctx.fs`), then the block lists, and `src/urls.ts` requests external URLs for `comark/dead-url`. `lintFiles()` parses each file once so links between files share one heading index. Tests stub `fetch`; they never hit the network.
  - `src/config.ts` loads the other packages in this repo through optional dynamic imports; they are optional peer dependencies. Add a new package there.
  - `src/rules/` is the catalog: every rule's code and title, the core ones in `core.ts` and one file per package. Each package's codes take their own hundred (annotate `COMARK01xx`, cards `02xx`, …); a new package takes the next one and adds its file to `src/rules/index.ts`.
  - `src/doctor.ts` is `comark-linter/doctor`. Vite Doctor has no Markdown visitor, so its Rules are manifest Rules that glob the Markdown in `onProjectEnd`. The root `doctor.config.ts` lints `docs/pages` and every package's `docs/` with it as part of `pnpm run doctor`.
- `packages/mark` is `comark-mark`, markdown-it-mark and markdown-it-sup ported to TypeScript. Marks are renamed to `mdc_inline_span`, since Comark drops `mark_open`, and `^` right after `[` never opens a superscript, so `[^1]` stays a footnote reference. The AST stays plain `mark` and `sup`; the components of each renderer add the `cmk-` classes and styles, so the plugin still works without them.
- `packages/links` is `comark-links`: two named plugins and no default export. `external()` in `src/external.ts` writes `target` and `rel` on external `a` nodes and appends the new-tab warning's spans while parsing, keeping an author's own `{target}` and `{rel}`, and adds one `links-styles` node for the styles. `anchors()` in `src/anchors.ts` only writes an `anchor` attribute on headings with an id; the components replace `h1` to `h6` and draw the link after the heading in a `.cl-heading` wrapper, so the tree keeps its headings for `docs/build.ts`'s sidebar and search. The HTML renderer also replaces `span` for the warning's `.cl-icon`, because Comark writes `aria-hidden="true"` as a bare `aria-hidden`, which screen readers ignore. No script.
- `packages/properties` is `comark-properties`. Its parse plugin reads the frontmatter keys in its `keys` option and writes them as a `properties` node of plain `div`/`dt`/`dd` rows, with pull request and issue links shortened to `owner/repo#123` and lists as `.cfm-tag` badges, where `::properties` sits or, with `top`, first in the document. No script: the components add the styles on mount.
- `packages/sources` is `comark-sources`. Its parse plugin reads the one `::sources` list, turns each `:cite[n]` (or `:cite[1,3]`) into a plain `sup` of links to `#cso-n` with the source's title, and gives each source `li` a back-link to every citation of it, so no renderer counts anything. The `sources` component draws the list and carries the styles for the markers too. No script.
- `packages/table` is `comark-table`. Its parse plugin reads `::table{src}` (from disk under `root`, like comark-include, or through `read`), a csv, tsv, or json fence inside `::table`, and bare csv and tsv fences, into a plain `table` inside a `data-table` node, since `::table` shares its name with Markdown tables. With `sort`, it makes the headers `.ctb-sort` buttons. Its script, built like carousel's, sorts and copies; the bar's markup is one string from `bar()` in `src/client.ts` that every renderer inlines.
- `packages/steps` is `comark-steps`. Its parse plugin groups each heading at `level` in `::steps`, and what follows it, into a `step` with its `index`, or each item of the one numbered list inside, so no renderer splits children. The numbers are a CSS counter. No script: the components add the styles on mount.
- `packages/quiz` is `comark-quiz`: `::question`, `::poll`, and `::recall` for lessons, read by one parser and drawn by one renderer.
  - `src/read.ts` turns each block into a prompt, its task-list options with their `>` rationales, and its slots, and reports its issues. Each option's `key` is a hash of its text, a question's options are shuffled with a seed from its id and keys, and an id an author leaves out is a hash of the prompt and options, so neither depends on where the block sits. Questions and recall cards share one number. A block inside another renders as plain content.
  - `src/html.ts` is the only renderer, since the blocks need its script. Without the script, a question's answer key, rationales, and explanation sit in a `<details>`, and the script moves them where the interactive form reveals them. The root carries `data-quiz-id` and `data-quiz-kind`, and each option `data-key`, plus `data-correct` on right ones, which hosts read from the server's HTML.
  - `src/script.ts` is the inlined browser script: one instance in `window.__comarkQuiz`, a MutationObserver for later blocks, `comark-quiz:answer` events, `comark-quiz:ready`, and `comark-quiz:state` from a host, with answers in localStorage until a host sends state. Its host contract is a public API that Drop codes against, so change its events and fields only on purpose.
- `packages/cards` is `comark-cards`. Its parse plugin replaces each `::card`'s attributes with the ones it renders from, puts its title (`title` or a `#title` slot) in a `card-title` node, and resolves its `icon` through comark-icon's `Icons`; a card with `to` is covered by one stretched link. `::columns` wraps each child that isn't a `:::column` in one, so no renderer splits children. No script: the components add the styles on mount.
- `packages/badge` is `comark-badge`. Prose badges normalize to `color` plus inline content. Image badges normalize to `src` and `label`: a local SVG data URI for static content, or a hosted URL for live npm and GitHub Actions data. `src/svg.ts` owns options and SVG drawing; `src/server.ts` exports the bounded, cached public-data handler used by `docs/worker.ts` at `/badge.svg`. The builder in `docs/badges/` uses the same options; `docs/build.ts` renders it inside the shared docs shell at `/badges/`, with an inline script that initializes again after island navigation. Image generation and server fetching have separate exports; renderers only draw the normalized node.
- `packages/qr` is `comark-qr`. Its parse plugin encodes each `:qr{value}` with uqr, a zero-dependency ES module and the package's one dependency, and writes `value`, `size` (modules, quiet zone included), and `path`, the dark modules as one SVG path of row runs, so no renderer encodes anything or sets inner HTML. No script: the components add the styles on mount.
- `packages/fields` is `comark-fields`. Its parse plugin replaces each `::field`'s attributes with `name`, `type`, `required`, and `default` as strings (`:required="true"` and a JSON `:default` included), so the renderers only draw them; nested `:::field` blocks render inside their parent's body. No script: the components add the styles on mount.
- `packages/reading-time` is `comark-reading-time`. Its parse plugin writes `meta.readingTime = { words, minutes }` from the text outside code blocks, counting each CJK character as a word, and draws nothing, so it has no renderers and no classes.
- `packages/file-tree` is `comark-file-tree`. Its parse plugin reads the fenced block inside `::file-tree`, indented by two spaces or pasted from `tree`, into nested `file-tree-item` nodes with `type`, `name`, `state`, `note`, and, when it's given comark-icon's `Icons`, `icon`, so no renderer parses lines. A Markdown list inside gets an issue, because Comark turns names in it into markup. Folders are `<details open>`; no script.
- `packages/details` is `comark-details`. Its parse plugin turns `::details`, each `:::accordion-item`, and `::collapsible` into a `disclosure` node, drawn as `<details>`, whose first child is a `disclosure-summary` holding the label, so a `#summary` slot renders as a real `<summary>`. A `type="single"` accordion gives its items one `name` from a hash of the source, and Nuxt UI's `defaultValue` becomes `open`. No script: the components add the styles on mount.
- `packages/tabs` is `comark-tabs`. Its parse plugin turns `::code-group` into `::tabs` and gives each `tabs-item` its label and position, and the `tabs` node every label and a `uid` from a hash of the source, so no renderer splits children and the HTML renderer's ids differ between documents on one page. Its script is built like carousel's.
- `packages/outline` is `comark-outline`, named so because npm refuses `comark-toc` as too close to `remark-toc`; its block is still `::toc`. Its parse plugin reads every heading with an id itself, rather than relying on running after Comark's toc plugin, and replaces each `::toc` with a `toc` node holding a nested `ul` of links to the h2 headings down to `depth`. `[[toc]]` isn't read: Comark parses `[[...]]` as a span. No script: the components add the styles on mount.
- `packages/xref` is `comark-xref`. Its parse plugin numbers images alone in their paragraph and elements with a `fig-` id, and `::table`s with a `tbl-` id, in document order, wraps such an image in a `figure` with a numbered `figcaption`, gives a table a numbered `caption`, and replaces each `:ref{#id}` with a link that reads "Figure 1". Its output is plain elements, so it has no renderers and ships no styles. Pandoc's `@fig-x` isn't read, since `@name` is a mention in comark-chips and comark-github.
- `packages/tests` is `comark-tests`. Its parse plugin reads a JUnit report from `::tests{src}` (from disk under `root`, like comark-include, or through `read`) or an xml fence inside the block, with the small XML parser in `src/xml.ts`, and replaces the block with a `tests` node holding `passed`, `failed`, `skipped`, `duration`, and `title`, whose children are one `details` per failure. No script: the components add the styles on mount.
- `packages/ui` is `comark-ui`: every other package in one install, and the one the docs recommend. It has no docs page of its own, since `docs/pages/getting-started.md` is its page, and its homepage is the site. `preset()` in `src/index.ts` takes one renderer's entries of the packages with components, adds the parse-only ones itself, and returns `{ plugins, components }` in the order the docs render with, with one `createIcons()` shared by icon, cards, details, file-tree, tabs, and code. Each renderer entry only passes its imports, and Vue, React, and Svelte leave out annotate and diff. It re-exports comark-critic's `css` as `criticCss`, since a project can't import a dependency of a dependency. It also registers comark-pele, a third-party plugin, under `mermaid`: `src/client.ts` maps Pele's `--pele-*` variables to the `--comark-*` tokens on its `.pele-diagram` card, and each entry adds those styles the way a package's components do. `docs/plugins.ts` renders the site through it, and comark-linter loads it before the separate packages. Add a new package here too.
  - Its build copies the agent skill from the root `skills/comark-ui` into `dist/skills`, so apps can bundle the skill that matches the plugins they installed.
- `packages/zoom` is `comark-zoom`.
  - `src/index.ts` is the parse plugin. It marks content images and adds one `zoom-runtime` node to a document with anything to zoom.
  - `src/script.ts` is the browser script. `script()` is self-contained because the HTML renderer inlines its source. `src/client.ts` exports `start()`, which runs it with the bundled styles; Vue, React, and Svelte components call it on mount and stop it on unmount.
  - `src/theme.ts` resolves the shared `--comark-*` tokens, and `comark-zoom/theme` exports it alone. `comark-github`, `comark-embed`, and `comark-tabs` have it as a dev dependency and bundle only this entry, so they don't install zoom or carry its styles.
  - `src/html.ts`, `src/vue.ts`, `src/react.ts`, and `src/svelte/` are the renderers. They all output the same markup.
- `shared/markdown-it.ts` is bundled by each package that adds Markdown syntax, so it isn't published on its own. Comark builds nodes from a closed table of token types, so these plugins emit `blockquote` or `mdc_inline_span` tokens with their own tag, never `mdc_block_slot`, which a `::component` reads as a named slot. It also places rules next to anchors that may be missing, as Comark's are under `registerDefaultPlugins: false`, and keeps one markdown-it function per set of options, since Comark caches parsers by their identity.
- `skills/comark-ui` is the one agent skill. `npx skills add onmax/comark-ui` installs it from GitHub, the docs serve it under `/.well-known/skills/` through nuxt-agent-discovery, and comark-ui ships it. `SKILL.md` installs the plugins, routes each block to its package's reference in `references/`, and holds what several packages share, such as the marks. `test/workspace.test.ts` checks that every package has a reference linked from `SKILL.md` that ends with its Register section, so a new package adds one and a change to a package's syntax updates it.
- `docs/pages/doctor/` is the linter's rules, under Linter in the rail: an overview and one page per rule, at `doctor/<rule without comark/>.md`, with no frontmatter, since `docs/doctor.ts` takes the title from the catalog. Each page has an `::incorrect` and a `::correct` block around one fenced example, and `test/doctor.test.ts` checks that every rule has a page, that the incorrect example reports its rule alone, and that the correct one reports nothing. Vite Doctor links each code to its page.
- `docs/` builds the docs site with the plugins themselves. Cloudflare serves it from `docs/dist`. The site is laid out like ui.nuxt.com: a rail of a few sections (Docs, Components, Typography, Linter, Playground), each with a column of its pages. Each package has one page, `docs/index.md` in its own folder, which `files` keeps out of npm, written for comark-ui users in the shape `docs/WRITING.md` gives; read it before writing or restructuring any page. API ends with `### Package`, which installs and registers the package alone. A block's page has no installer: Getting started installs comark-ui. Annotate's components, and the parts of a chart with syntax of their own (`annotation`, `gantt`, `vega-lite`), also get a page each in `docs/components/`, in the order the package's page links them. The page's frontmatter gives the block's name as `title`, and its group, icon, blurb, and credits; the group picks the section (Review blocks, Docs blocks, and Page behavior are Components, Markdown syntax is Typography, Authoring tools are the docs' Utilities, Linter is the linter's), and a section lists its packages by name. Search reads every page's title, headings, and text, so a page's `keywords` frontmatter lists only the words people search for that it doesn't say, such as other tools' names for its blocks. `packageOrder` in `docs/build.ts` orders the examples on the landing page and in the playground. comark-linter keeps several pages. `docs/worker.ts` redirects the old per-topic pages to each package's page. `docs/pages/` holds the rest of the site: the landing page, guides, recipes, and comparisons. `docs/plugins.ts` is the one list of plugins the pages and the playground render with. `docs/play.ts` is the playground, bundled with Vite; its presets are the examples at the top of each page. `docs/build.ts` renders every page and writes each one's body to `docs/.generated/pages/`; the Nuxt app in `docs/app` only serves those bodies as server islands, for client-side navigation, so change a page's markup in `build.ts`, never in the app. `docs/style.css` lists every class that draws its own frame, in the `.example-preview` rules and the `.demo-page` card rule, so an example or a landing card doesn't frame it again; a new package with a bordered block adds its class to both.

## Rules

- Follow the 90/10 rule. If a feature would take most of the code for a small share of users, leave it out.
- Test through the public interface: parse plus render. Don't test internals.
- Rendering never throws. Problems go in `meta.issues`, one sentence each that names the block and the fix. Every plugin appends to the list and never replaces it, since several run on one document.
- Each issue also names its rule, `comark/<package>/<kind>`, in `meta.issueRules`, keyed by the sentence; plugins merge into it the same way. A new kind of issue needs its rule in `packages/lint/src/rules/<package>.ts` and a page in `docs/pages/doctor/<package>/`.
- Comments are rare and explain why, never what.
- Each package's classes start with its own prefix, since every package's styles share the `comark` layer: `ca` annotate, `cc` carousel, `cch` charts, `cp` chips, `ck` code, `cd` diff, `ce` embed, `cgc` github, `ci` icon, `ckb` keys, `cs` steps, `ccr` cards, `cb` badge, `ct` tabs, `cz` zoom, `cca` cast, `cm` media, `cqr` qr, `cfl` fields, `cft` file-tree, `cdt` details, `cco` colors, `ccm` critic, `cl` links, `cfm` properties, `cso` sources, `cdg` diagrams, `cmt` metrics, `cfn` footnotes, `cxr` xref, `cn` code-notes, `ctr` tests, `cqz` quiz, `cmk` mark, `cmh` math. Pick an unused one for a new package.
- Every build runs publint, so a package whose `exports`, `files`, or types don't resolve fails to build. Svelte entries ship as source with a hand-written `index.d.ts`; keep it in step with the components' props.
- `pnpm ready` formats, lints, typechecks, builds, tests, and runs Vite Doctor with the strict TypeScript preset (each package's `doctor.config.json`). Run it before opening a PR; CI runs the same steps.
- Use conventional commit titles. uppt builds the release from them (see Releasing below).
- Never comment on issues or pull requests without explicit consent.

## Releasing

uppt opens a draft `release/vX.Y.Z` PR from conventional commits on `main`, in lockstep for every package matched by `packages/*`. Merging it tags the version and publishes each package to npm through OIDC trusted publishing, with no approval step. A new package needs a trusted publisher on npmjs.com before its first release, with workflow `release.yaml`, environment `npm`, and `npm publish` allowed. If publishing fails after the tag exists, run `gh workflow run release.yaml --repo onmax/comark-ui --ref vX.Y.Z`. The docs deploy through Cloudflare Workers Builds on every push to `main`.
